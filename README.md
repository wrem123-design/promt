# 프롬프트 아카이브

이미지를 업로드하고 AI 이미지 생성용 프롬프트를 저장·편집·복사하는 **로컬 앨범형 프롬프트 저장소**입니다.

브라우저에서 이미지를 압축한 뒤, Node 서버가 `data/` JSON과 `uploads/` 이미지 파일로 상태를 영속 저장합니다.

---

## 실행 방법

Windows에서 `run-server.bat`를 실행합니다.

| 항목 | 값 |
|------|-----|
| 기본 주소 | http://127.0.0.1:5173 |
| 포트 변경 | 환경 변수 `PORT` |
| 바인딩 주소 변경 | 환경 변수 `HOST` (기본 `127.0.0.1`) |
| 원격 접속 허용 | `ALLOW_REMOTE=1` (인증이 없으므로 권장하지 않음) |
| 요청 크기 상한 | 환경 변수 `MAX_REQUEST_MB` (기본 150) |

Node.js가 PATH에 있어야 합니다. 포트가 이미 사용 중이면 기존 서버 페이지를 엽니다.
이 앱에는 로그인 기능이 없으며 기본 설정은 같은 PC에서만 접근할 수 있습니다.

### 안전한 시작과 임시 저장

- 첫 화면은 서버 상태 확인이 끝날 때까지 편집을 잠가 샘플 데이터가 기존 아카이브를 덮지 않도록 합니다.
- 서버가 끊기면 저장 상태가 **브라우저 임시 저장**으로 바뀌고, 상단 상태 버튼으로 재연결할 수 있습니다.
- 브라우저 임시본과 서버 데이터가 함께 있으면 수정 시각을 비교합니다. 서버가 더 최신이면 서버 데이터를 우선하며, 수동 재연결 중 충돌하면 어떤 쪽을 유지할지 확인합니다.
- 손상되었거나 수정 시각 정보가 없는 오래된 임시본은 기존 서버 데이터를 자동으로 덮지 않습니다.

### 유사 프롬프트 찾기

갤러리의 **정렬**에서 **유사순**을 선택하면 현재 검색·필터 결과 안에서 의상과 배경이 가장 닮은 항목끼리 붙여서 표시합니다. 카드에는 `유사 88%`와 짝이 된 항목의 제목이 함께 표시됩니다.

1. 필요하면 검색, 카테고리, 복장·배경 필터로 비교 범위를 좁힙니다.
2. **정렬 → 유사순**을 선택합니다.
3. 상단의 높은 퍼센트 짝부터 확인하고 필요 없는 항목을 삭제합니다. 삭제 직후 남은 항목은 현재 목록을 기준으로 새 짝과 점수를 계산하므로 더 이상 비슷한 상대가 없으면 아래로 이동합니다.

유사도는 **의상 50% + 배경 50%**로 계산합니다. 각 문단 안에서는 정규화된 단어, 이어지는 단어 묶음, 공백에 영향받지 않는 문자 패턴을 함께 비교합니다. 제목, 태그, 외모, 표정·포즈, 디테일 문단은 계산에서 완전히 제외합니다. `100%`는 대소문자·구두점·연속 공백을 정리한 의상과 배경 문단이 둘 다 같은 경우에만 표시됩니다.

유사도는 중복 가능성을 빠르게 살펴보기 위한 로컬 참고값이며 의미를 해석하는 별도의 AI 분석은 아닙니다. 의상이나 배경 문단이 없는 분석 대기 항목은 비교 대상 없음으로 표시됩니다. 계산은 브라우저에서만 실행되며 외부 API나 추가 설정이 필요하지 않습니다.

### 중복 판정과 업로드 차단

업로드 설정의 **중복 업로드 감지 (파일 + 의상·배경 프롬프트)**를 켜면 같은 이름·용량의 파일을 먼저 확인하고, EXIF 가져오기 또는 AI 분석으로 프롬프트가 준비된 뒤 현재 아카이브와 다시 비교합니다. 의상과 배경 문단이 모두 같으면 외모·표정·포즈·디테일이 달라도 중복으로 판정하여 새 항목을 저장하지 않습니다.

갤러리의 **중복** 필터와 카드의 중복 배지도 같은 의상·배경 기준을 사용합니다. 프롬프트가 없는 항목은 기존 파일 정보만으로 확인하며, 유사하지만 완전히 같지 않은 의상·배경은 중복으로 차단하지 않고 유사순 점수로만 보여줍니다.

## PNG → WebP 폴더 변환기

오른쪽 상단의 **변환** 버튼은 폴더 전체 또는 직접 고른 PNG를 WebP로 변환합니다. 변환은 브라우저 안에서 로컬로 처리됩니다. 기본적으로 원본 PNG는 그대로 보존하며, 폴더 선택 모드에서만 변환 성공 원본을 영구 삭제하도록 선택할 수 있습니다. ComfyUI가 PNG의 `prompt`, `workflow` 등에 저장한 텍스트 메타데이터와 PNG `eXIf` 청크는 WebP의 EXIF/XMP 청크로 옮겨집니다.

### 사용 방법

1. 앱 오른쪽 상단에서 **변환**을 누릅니다.
2. **폴더 선택** 또는 **개별 파일** 모드를 고릅니다.
   - **폴더 선택**: PNG 폴더를 고르고, 필요하면 하위 폴더 검색을 켭니다.
   - **개별 파일**: 확장된 선택 영역으로 PNG를 끌어놓거나 **파일 선택**에서 여러 장을 고릅니다. 같은 파일은 중복 선택되지 않습니다.
3. 선택을 다시 시작하려면 **선택 비우기**를 누릅니다.
   - 폴더 선택 모드에서 **변환 후 원본 영구 삭제**를 켜면 WebP 저장에 성공한 PNG만 작업 마지막에 삭제됩니다.
   - 실행 전 복구 불가 확인창이 한 번 더 표시됩니다. 건너뜀·변환 실패 파일은 삭제하지 않습니다.
4. 저장 위치를 선택합니다.
   - **원본 폴더**: 폴더 선택 모드에서 각 PNG와 같은 폴더에 WebP를 저장합니다.
   - **지정 폴더**: 브라우저의 폴더 선택 창에서 별도의 저장 폴더를 지정합니다.
   - 개별 파일 모드는 브라우저 보안상 원본 파일의 쓰기 위치를 알 수 없으므로 **지정 폴더**를 사용합니다.
5. WebP 화질과 같은 이름의 기존 WebP 처리 방식을 선택합니다.
6. **WebP 변환 시작**을 누르고 현재/전체 파일 수와 진행률을 확인합니다. 변환 창을 닫아도 작업은 계속되며 화면 오른쪽 아래 축소 진행바를 누르면 다시 열 수 있습니다.

### 변환 설정

| 설정 | 옵션 | 기본값 |
|------|------|--------|
| WebP 화질 | 70~100 | 100 |
| 하위 폴더 | 검색 안 함 / 검색하고 구조 유지 | 검색 안 함 |
| 저장 위치 | 원본 폴더 / 지정 폴더 | 원본 폴더 |
| 파일명 충돌 | `_webp` 이름으로 저장 / 건너뛰기 / 덮어쓰기 | 새 이름으로 저장 |
| 메타데이터 | PNG 텍스트·EXIF를 WebP EXIF/XMP로 기록 | 항상 활성화 |
| 원본 처리 | 보존 / 변환 성공 후 영구 삭제 | 보존 |

예를 들어 `Krea2_001.png`가 있고 같은 이름의 WebP가 없다면 `Krea2_001.webp`로 저장됩니다. 기존 `Krea2_001.webp`가 있고 기본 충돌 옵션을 사용하면 `Krea2_001_webp.webp`로 저장됩니다.

변환이 끝나면 **메타데이터 유지 활성화** 상자의 오른쪽에 최근 변환 2회의 완료 시각, 저장 폴더 이름, 전체 파일 수와 완료·원본 삭제·건너뜀·오류 수가 표시됩니다. 이 기록은 브라우저에 보관되어 앱을 다시 열어도 유지됩니다.

## LoRA별 이미지 분류

오른쪽 상단의 **사진 분류** 버튼은 ComfyUI 생성 이미지의 `prompt` 메타데이터를 읽어 `Power Lora Loader (rgthree)`에서 실제로 켜진(`on: true`) LoRA별로 파일을 이동합니다. 비활성 목록과 별도의 고정 `LoraLoaderModelOnly` 노드는 분류 기준에서 제외합니다.

### 사용 방법

1. **사진 분류**를 누르고 **생성 이미지 폴더**를 선택합니다. 현재 폴더의 WebP·PNG·JPG를 즉시 검사하며 필요하면 **하위 폴더 포함**을 켭니다.
2. 감지된 LoRA 이름과 이미지 수를 확인합니다.
   - LoRA 하나만 켜진 이미지는 해당 LoRA 한 줄에 표시됩니다.
   - 여러 LoRA가 동시에 켜진 이미지는 `LoRA A + LoRA B`처럼 별도 조합으로 표시됩니다.
   - 메타데이터를 읽지 못한 이미지는 **판독 불가**로 남고 자동 이동하지 않습니다.
3. 인물 분류에 사용하지 않을 스타일·품질 LoRA는 **감지 제외 LoRA**에 등록합니다.
   - 이름을 직접 입력하거나 감지 결과에 표시되는 각 LoRA의 **제외**를 누를 수 있습니다.
   - 예를 들어 `H2H_Stella_v1 + PornMaster_Krea2_Realism_slider_V1`에서 PornMaster를 제외하면 재검사 없이 `H2H_Stella_v1`로 즉시 다시 묶입니다.
   - 폴더 경로, 영문 대소문자, `.safetensors`·`.ckpt`·`.pt` 확장자는 무시하고 LoRA 파일의 기본 이름으로 일치시킵니다.
   - 제외 LoRA만 켜진 이미지는 **감지 제외 LoRA만 있음**으로 남으며 인물 LoRA 폴더로 자동 이동하지 않습니다.
4. 목적지를 지정합니다.
   - **자동 분류 기준 폴더**를 선택하면 그 안에 LoRA 이름의 하위 폴더를 자동으로 만듭니다.
   - 특정 LoRA의 **개별 지정**을 누르면 그 항목만 다른 폴더로 보냅니다. 개별 지정이 자동 기준 폴더보다 우선합니다.
   - 자동 기준 폴더를 선택한 상태에서는 개별 폴더를 지정하지 않은 항목도 자동 하위 폴더로 이동합니다. 이동시키지 않을 항목은 **이동 안 함**을 누르고, 다시 대상으로 돌릴 때는 **이동 포함**을 누릅니다.
   - 자동 기준 폴더를 선택하지 않았다면 **개별 지정**한 항목만 이동합니다.
5. 같은 파일명이 이미 있을 때 새 이름(`_2`, `_3`…)으로 이동할지 건너뛸지 선택합니다. 기존 파일을 덮어쓰는 옵션은 제공하지 않습니다.
6. **LoRA별 폴더로 이동**을 누르고 확인창을 승인합니다. 창을 닫아도 작업은 계속되며 오른쪽 아래 축소 진행바를 눌러 다시 열 수 있습니다.

원본 폴더, 자동 기준 폴더, LoRA별 개별 목적지, **이동 안 함** 목록, **감지 제외 LoRA** 목록, 하위 폴더 포함 여부와 파일명 충돌 옵션은 브라우저에 자동 저장됩니다. 앱을 껐다 다시 열어도 복원되며, 브라우저 보안 정책에 따라 저장된 폴더의 접근 권한을 한 번 다시 승인해야 할 수 있습니다.

파일 이동은 목적지 파일 쓰기와 파일 크기 검증이 모두 성공한 뒤 원본을 영구 삭제하는 방식입니다. 원본과 목적지가 같은 폴더인 항목, 저장 실패 항목, 검증 실패 항목은 원본을 삭제하지 않습니다. Windows 휴지통을 사용하지 않으므로 실행 전에 목적지와 감지 수량을 확인하세요.

Image Saver Simple이 직접 만든 WebP의 EXIF `Model` 태그와 이 앱에서 PNG→WebP로 변환하며 만든 XMP/EXIF 래퍼를 모두 지원합니다. 이미지에 ComfyUI `prompt` 메타데이터가 없거나 `Power Lora Loader (rgthree)` 노드가 저장되지 않았다면 LoRA를 판별할 수 없습니다.

### ComfyUI EXIF 프롬프트 읽기

설정의 업로드 처리 방식을 **EXIF / 메타데이터 프롬프트 읽기**로 선택하면 이미지 분석 API 없이 ComfyUI가 저장한 프롬프트를 5개 섹션으로 가져옵니다.

- 워크플로우에 여러 프롬프트 입력이 함께 저장되어 있어도 `CLIP Text Encode (Positive Prompt)`의 연결을 역추적합니다.
- `ImpactSwitch`의 실제 `select` 값에 연결된 입력만 사용하며 비활성 Switch의 기본 문장은 제외합니다.
- `ImpactWildcardProcessor`에서는 와일드카드 구문이 아니라 실행 시 확장된 `populated_text`를 사용합니다.
- 사용자 외모와 랜덤 시나리오를 결합한 `easy promptConcat` 경로도 실제 구분자를 포함해 복원합니다.
- 앱에서 만든 시나리오는 저장된 4개 섹션과 정확히 대조하고, 과거 통합 시나리오는 카메라·촬영 문장 경계를 이용해 외모/복장/배경/표정·자세/디테일로 나눕니다.

수정 이전에 잘못 가져온 항목은 축소 저장 이미지에 원본 EXIF가 남아 있지 않을 수 있습니다. 이 경우 원본 ComfyUI 이미지 파일을 다시 업로드해야 하며, 새로 가져온 항목부터 실제 선택 스위치 경로가 적용됩니다.

### 프롬프트 5문단 분류 규칙

AI 이미지 분석과 추가 요청을 통한 프롬프트 수정은 다음 문단 경계를 동일하게 적용합니다.

- **외모**: 인물의 고정된 신체 특징과 헤어스타일만 포함합니다.
- **복장**: 의류, 액세서리, 착용물, 손에 든 물건만 포함합니다.
- **배경**: 장소, 건축물, 가구, 풍경, 주변 사물, 날씨 등 환경만 포함합니다. 인물의 외모·복장·자세·행동·시선·표정과 카메라·구도 지시는 제외합니다.
- **표정 및 자세**: 자세, 행동, 신체 배치, 손·다리 동작, 카메라·프레이밍, 시선, 고개 방향, 표정만 포함합니다. 외모·복장 상세와 장소·배경 묘사는 제외합니다.
- **디테일**: 조명, 화질, 카메라 스타일, 사실감, 질감, 색감, 그레인, 블러, 선명도, 제외 지시 등 기술적 표현만 포함합니다.

영문과 한국어 문장은 같은 문장 ID로 1:1 대응해야 합니다. 설정에서 분석 규칙을 수정할 때도 각 문단의 경계는 유지해야 합니다.

### Google Vertex AI 모델 분리 설정

설정의 **Google Vertex AI** 공급자에서는 이미지 분석 모델과 번역 모델을 별도로 지정할 수 있습니다.

1. **이미지 분석 모델**에는 업로드 이미지를 읽고 5문단 프롬프트를 생성할 모델을 지정합니다.
2. **번역 모델**에는 한국어 번역, 제목 요약, 텍스트 프롬프트 수정에 사용할 모델을 지정합니다.
3. 각 입력에서 `gemini-3.6-flash`, `gemini-3.5-flash-lite` 프리셋을 선택하거나 다른 Vertex 모델 ID를 직접 입력한 뒤 **설정 저장**을 누릅니다.

두 모델은 서로 덮어쓰지 않고 `providers.json`의 `visionModel`, `textModel`로 각각 저장됩니다. 프리셋은 모델 ID 입력을 돕는 목록이며 실제 사용 가능 여부는 Google Cloud 프로젝트, Vertex AI 모델 제공 상태, 선택한 Location에 따라 달라집니다. Vertex Service Account JSON과 해당 프로젝트의 Vertex AI API 권한이 필요합니다.

### 와일드카드 업데이트와 전체 갱신

변환 창 아래의 와일드카드 라이브러리에는 두 가지 갱신 방식이 있습니다.

1. 앱 오른쪽 상단에서 **변환**을 누릅니다.
2. 목적에 맞는 버튼을 누릅니다.
   - **와일드카드 업데이트**: 이전 처리 이후 추가된 새 항목만 기존 파일 끝에 추가합니다.
   - **전체 갱신**: 현재 `data/items.json`에 남아 있는 항목만으로 설정된 외모·시나리오 파일을 처음부터 다시 작성합니다.
3. 완료 문구에서 처리한 항목 수와 출력 파일별 줄 수, ComfyUI 새로고침 결과를 확인합니다.

- `appearance` 문단은 카테고리와 관계없이 설정된 외모 파일에 한 줄로 추가됩니다. 기본값은 `items/appearance.txt`이므로 `nsfw` 항목의 얼굴·외모도 기존처럼 얼굴 와일드카드에 포함됩니다.
- `outfit → background → expression_pose → details` 네 문단은 얼굴을 제외한 시나리오 한 줄로 합쳐집니다.
  - 기본 설정에는 카테고리 이름 `nsfw`를 `items/nsfw.txt`로 보내는 NSFW 규칙이 포함됩니다. ComfyUI에서는 `__items/nsfw__`로 사용할 수 있습니다.
  - 어떤 규칙에도 맞지 않는 항목은 기본 시나리오 파일인 `items/scenario.txt`에 저장됩니다.
  - 카테고리 이름의 영문 대소문자와 앞뒤 공백은 구분하지 않으며, 위에서부터 처음 일치한 활성 규칙 하나를 사용합니다.

#### 와일드카드 분류 규칙 설정

설정의 **분류/태그 설정 → 와일드카드 분류 규칙**에서 출력 구성을 바꿀 수 있습니다.

1. **얼굴·외모 저장 경로**와 **규칙 미일치 시나리오 경로**에 `wildcards/items` 폴더 기준 상대 경로를 입력합니다.
2. **규칙 추가**를 누르고 규칙 이름, 카테고리 조건, 저장 상대 경로를 지정합니다.
   - 카테고리 조건을 쉼표로 구분하면 여러 카테고리 이름을 하나의 출력 파일로 묶을 수 있습니다.
   - 규칙의 **사용**을 끄면 해당 규칙은 건너뛰며, 위·아래 버튼으로 우선순위를 바꿀 수 있습니다.
3. **분류 설정 저장**을 누른 뒤 와일드카드 업데이트 또는 전체 갱신을 실행합니다.

저장 경로는 `.txt` 상대 경로만 허용합니다. `scenes/nsfw.txt`처럼 하위 폴더를 사용할 수 있지만 절대 경로, 드라이브 경로, `..`, 중복 출력 경로, Windows 예약 파일명은 거부됩니다. 예를 들어 `scenes/nsfw.txt`는 ComfyUI에서 `__items/scenes/nsfw__`로 사용합니다.

규칙의 카테고리 조건이나 출력 경로, 기본 시나리오 경로, 외모 경로를 바꾸면 다음 **와일드카드 업데이트**가 현재 아카이브에서 확인되는 기존 줄을 새 대상 파일로 옮깁니다. 이전 파일의 관련 없는 수동 작성 줄은 유지합니다.

- 처리한 항목 ID는 `data/wildcard-sync-state.json`에 기록됩니다. 같은 버튼을 다시 눌러도 이미 처리한 항목이나 기존 파일과 같은 문장은 중복 추가되지 않습니다.
- **와일드카드 업데이트**는 새 ID만 추가하고 현재 규칙과 달라진 기존 줄만 파일 사이에서 옮깁니다. 수동으로 만든 다른 줄은 유지합니다.
- **전체 갱신**은 동일한 외모·시나리오 문장을 각 대상 파일에서 한 번만 기록하고 처리 기록도 현재 ID와 관리 경로로 재설정합니다. 따라서 아카이브에서 삭제한 프롬프트는 와일드카드에서도 사라집니다.
- 전체 갱신은 관리 중인 출력 파일에 수동으로 추가한 줄도 제거합니다. 실행 전 확인창에서 이 동작을 다시 안내하며, 설정된 출력 파일과 처리 상태 파일은 함께 교체되고 실패하면 기존 파일로 복구됩니다.
- 필수 영문 문단이 비어 있는 항목은 기록하지 않고 다음 실행에서 다시 확인합니다.
- ComfyUI가 실행 중이면 Impact Pack 목록도 자동 새로고침합니다. ComfyUI가 꺼져 있으면 파일 업데이트만 완료되고, 다음 ComfyUI 실행 때 새 파일을 읽습니다.

기본 대상은 `D:\ComfyUI-Easy-Install\ComfyUI\custom_nodes\comfyui-impact-pack\wildcards\items`입니다. 다른 설치 경로를 사용할 때는 서버 실행 전에 `COMFYUI_WILDCARD_DIR` 환경 변수로 대상 폴더를 지정할 수 있고, 새로고침 주소는 `COMFYUI_WILDCARD_REFRESH_URL`로 바꿀 수 있습니다.

로컬 API는 `POST /api/wildcards/sync`를 증분 업데이트에 사용하고, `POST /api/wildcards/sync?mode=rebuild`를 전체 갱신에 사용합니다. 증분 응답에는 `appearanceAdded`, `appearanceMoved`, `scenariosAdded`, `scenariosMoved`, 파일별 `scenarioOutputs`가 포함됩니다. 전체 갱신 응답에는 `rebuilt`, `validItems`, `invalidItems`, `appearanceWritten`, `scenariosWritten`, 파일별 `scenarioOutputs`, `duplicatesSkipped`, `refreshed`가 포함됩니다. 기존 연동 호환을 위해 `scenarioAdded`, `nsfwScenarioAdded`, `scenarioWritten`, `nsfwScenarioWritten` 필드도 유지합니다. 지원하지 않는 `mode`는 HTTP 400을 반환합니다.

### 요구 사항과 제한

- 폴더 읽기·쓰기를 지원하는 최신 Chrome 또는 Edge가 필요합니다. 브라우저 보안상 앱은 선택한 폴더의 전체 경로를 화면에 표시하지 않습니다.
- 최근 변환 기록에도 브라우저가 제공하는 폴더 이름만 표시되며 드라이브 문자를 포함한 전체 경로는 저장하지 않습니다.
- WebP 화질 100도 브라우저 인코더의 손실 압축입니다. 재편집용 무손실 원본은 PNG를 보관하세요.
- **변환 후 원본 영구 삭제**는 Windows 휴지통을 거치지 않으며 복구할 수 없습니다. WebP 쓰기와 메타데이터 검증을 완료한 파일만 삭제 대상으로 등록됩니다.
- 개별 파일 모드는 브라우저가 원본 위치의 삭제 권한을 받지 못하므로 영구 삭제 옵션을 사용할 수 없습니다.
- `prompt`, `workflow`, `tEXt`, `iTXt`, `zTXt`, `eXIf` 메타데이터를 처리합니다. 압축 텍스트 해제를 지원하지 않는 오래된 브라우저에서는 일부 `zTXt` 내용이 제외될 수 있습니다.

## 백업 / 임포트

### UI

**설정 → 고급 설정** 탭:

| 버튼 | 동작 |
|------|------|
| **전체 백업 저장** | 서버 `/api/backup`으로 게시물·설정·태그·공급자·업로드 이미지를 한 JSON 파일로 다운로드. API 비밀키는 기본 제외 |
| **백업 가져오기** | 위 JSON을 선택해 `/api/import`로 **교체 복원** (확인 대화상자 있음) |
| JSON 클립보드 복사 | 현재 메모리 상태 전체 JSON 복사 (이미지 바이너리 없음) |
| CSV 내보내기 | 게시물 요약 CSV 복사 |

가져오기 전에 반드시 **전체 백업 저장**으로 현재 상태를 받아 두는 것을 권장합니다.

### 백업 파일 형식

```json
{
  "format": "prompt-archive-backup",
  "version": 1,
  "exportedAt": "ISO-8601",
  "includeSecrets": false,
  "settings": { },
  "tags": { },
  "providers": [ ],
  "items": [ ],
  "images": {
    "img-xxx-display-abcdef.webp": "<base64>"
  },
  "stats": { "itemCount": 80, "imageCount": 240, "providerCount": 5 }
}
```

- `images`: 게시물이 참조하는 `uploads/` 파일만 base64로 포함
- 기본 백업에는 `providerSecrets`가 없습니다. UI에서 **API 비밀키 포함**을 명시적으로 선택하고 경고를 확인한 경우에만 포함됩니다.
- 비밀키가 없는 백업에서 공급자 설정을 가져오면 기존 키와 바뀐 엔드포인트가 결합되지 않도록 해당 공급자의 서버 키를 지웁니다. 가져온 뒤 다시 입력하세요.
- 구버전 클라이언트 내보내기(메타만) 및 전체 state dump 형식도 가져오기 시 호환 시도

### API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/backup` | 비밀키를 제외한 전체 백업 JSON |
| `GET` | `/api/backup?includeSecrets=1` | 비밀키를 포함한 전체 백업 JSON. 안전한 보관 필요 |
| `POST` | `/api/import` | body: 백업 JSON 또는 `{ "mode": "replace"\|"merge", "backup": { ... } }` |

- **replace** (기본): 설정·태그·게시물·이미지를 백업으로 교체. 참조되지 않는 `uploads/` 파일은 정리
- **merge**: 게시물을 id 기준으로 합침. 설정은 백업에 있을 때만 반영
- 가져오기 직전 현재 전체 상태는 `backup/pre-import-*.json`에 안전 백업으로 저장

기본 요청 본문 한도는 약 150MB입니다. 더 큰 아카이브는 `MAX_REQUEST_MB`를 올리세요.

### 권장 워크플로

1. 다른 PC/재설치 전: **전체 백업 저장** → JSON 파일을 안전한 곳에 보관
2. 복원: 서버 실행 후 **백업 가져오기** → 같은 JSON 선택
3. 기본 백업은 비밀키를 포함하지 않으므로 공유용으로도 이 방식을 유지

## 데이터·보안 주의

- `data/`, `uploads/`는 **git에 올리지 않습니다** (로컬 전용).
- `provider-secrets.json`과 이름에 `WITH-SECRETS`가 포함된 백업에는 API 키가 들어갈 수 있습니다. 공유·일반 클라우드 동기화를 피하세요.
- 서버는 기본적으로 `127.0.0.1`만 수신하며 정적 파일은 앱 셸과 검증된 업로드만 제공합니다.
- `ALLOW_REMOTE=1`은 인증을 추가하지 않습니다. 신뢰할 수 있는 격리망이 아니면 사용하지 마세요.

## 기술 스택

- 런타임: Node.js (외부 npm 의존성 없음, 표준 라이브러리 `http`/`fs`/`path`/`crypto`)
- 프론트: 바닐라 HTML/CSS/JS 단일 페이지
- 저장: JSON 파일 + `uploads/` 정적 이미지
