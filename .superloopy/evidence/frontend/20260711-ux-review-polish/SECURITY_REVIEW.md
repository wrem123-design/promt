# SECURITY_REVIEW

검증일: 2026-07-11
범위: `server.js`, `app.js`, 백업·가져오기, 공급자 비밀키, 정적 파일, 로컬 접근 경계

## 판정

기본 로컬 운영 기준 PASS. 발견된 Critical·High 항목은 수정하고 실제 임시 서버에서 재현 검증했다.

## 주요 수정

- 서버 기본 바인딩을 `127.0.0.1`로 제한하고, `ALLOW_REMOTE` 없이 외부 `HOST`를 지정해도 루프백으로 강제함.
- 소켓 주소, Host, Origin을 함께 검사함. 위조 Host·Origin 요청은 403.
- 정적 파일을 `index.html`, `app.js`, `styles.css`, 검증된 업로드로 한정함.
- `data/`, `.git/`, `backup/`, `server.js` 직접 요청은 404.
- 기본 백업에서 비밀키를 제외하고, 비밀 포함 백업은 루프백 요청에서만 허용하며 파일명에 `WITH-SECRETS`를 표시함.
- 공급자 공개 데이터는 허용 필드 목록만 저장·응답하며 pending, secret, token 계열 필드를 제거함.
- `/api/providers`뿐 아니라 `/api/state`에서도 API 대상 변경을 비교하고, 대체 키가 없으면 기존 비밀키를 제거함.
- 가져오기와 상태 저장에서 게시물 ID, 이미지 참조, 업로드 파일명, 이미지 매직 바이트를 검증함.
- CSP에서 인라인 스크립트를 차단하고 `nosniff`, frame 차단, referrer 제한을 적용함.
- JSON 저장은 임시 파일 작성 후 rename하며, 가져오기 직전 자동 안전 백업을 생성함.
- 최초 서버 확인 전 편집을 잠그고, 브라우저 임시본과 서버 파일 수정 시각을 비교해 오래된 전체 상태 덮어쓰기를 차단함.
- 업로드는 서버 또는 브라우저 임시 저장 완료를 기다린 뒤 완료로 표시하고, 둘 다 실패하면 원본 `File`을 재시도 목록에 유지함.

## 실제 검증

- 임시 복사 서버에서 테스트 키 저장 후 API URL 변경: 기존 키 제거 확인.
- 악성 게시물 ID·`javascript:` 이미지 주소: HTTP 400.
- `HOST=0.0.0.0`, `ALLOW_REMOTE` 미설정: 127.0.0.1 리스너로 강제.
- 현재 서버 민감 경로 5종: 모두 404.
- 위조 Host·Origin: 모두 403.
- 공개 공급자 응답의 pending·secret·token 필드: 0개.
- 수정 시각이 오래된 빈 임시본과 손상 JSON 임시본을 주입한 뒤 재시작: 서버의 140개 항목 유지, 임시본 제거 확인.
- `node --check app.js`, `node --check server.js`: PASS.

## 잔여 운영 주의

`ALLOW_REMOTE=1`은 호환을 위한 명시적 선택이며 인증과 TLS를 추가하지 않는다. 기본 로컬 실행을 유지하거나, 원격 사용 시 별도 인증 프록시와 TLS가 있는 신뢰 환경에서만 사용해야 한다.
